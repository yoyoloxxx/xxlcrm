# XXLcrm · оценка продукта и что сделано в v0.30

*22–23 августа 2026. Четыре независимых ревью (удобство, безопасность, конструктор/переход с конкурентов, качество кода) по коду v0.29 и живому билду, затем правки. Все цифры «до → после» — по итогам ревью и повторного прогона.*

## Итоговые оценки (10-балльная шкала)

| Измерение | Было | Стало | Что решило |
|---|---|---|---|
| Удобство | 6 | 8 | краш «Сводки» у справочников, пустая карточка без фокуса, массовое удаление без вопроса, чужие имена в демо, тач-элементы |
| Безопасность | 5 | 7,5 | подписка на уведомления по секрету, личные контакты не уезжают в базу, лимит и приманка в приёмнике, чистка устройства при выходе, код приглашения, `chat_append_msg`, CSP |
| Готовность к переходу с amoCRM/Битрикс/Excel | 5 | 7,5 | стадии/даты/ответственные/ФИО/телефон/связи/ID при импорте, причины отказа, сводка по сотрудникам, дубли |
| Качество и устойчивость | 6 | 8 | потеря данных во второй вкладке, удаление >700 записей, пагинация облака, слияние переписки, ресинк после разрыва, счётчик правил |

Что это значит для владельца бизнеса: базу теперь можно перенести из amoCRM или Битрикса без развала стадий и истории, CRM не теряет работу при второй вкладке и в команде, а посторонний не может ни подписаться на ваши заявки, ни завалить приёмник спамом.

## Что исправлено (по важности)

### Потеря данных — устранено
- **Вторая вкладка затирала работу первой** («Работать здесь» и автоповышение после сна ведущей вкладки писали устаревший снимок поверх базы). Теперь повышение — только через перечитывание, без единой записи.
- Ведомая вкладка больше **не забирает сообщения** из Telegram/WhatsApp/MAX (их нельзя было сохранить, а канал второй раз не отдаёт).
- Облако: удаление >700 записей одним запросом давало 414 и «НЕ сохраняется» навсегда — теперь пачками по 200; **отказ базы удалять чужое** (RLS) больше не превращает запись в «призрака» — она возвращается на экран с честным тостом.
- Облако отдаёт максимум 1000 строк на запрос — история и записи команды приезжали «дырявыми». Теперь постранично (и на сервере тоже).
- Переписка **сливается по id сообщений**: входящее от клиента, пришедшее пока менеджер набирал ответ, больше не пропадает.
- После сна ноутбука/обрыва realtime пространство **перечитывается само**; подавление «эха» больше не зависит от часов клиента.
- Счётчик срабатываний правил перестал притворяться «структурой, обновлённой коллегой» и затирать чужие правки правил; при конфликте структуры свои правила и маршруты не теряются.
- Пустую «свежую» карточку теперь удаляет только та вкладка, что её создала (коллега мог нажать «+ Сделка» и отвлечься).
- Календарь обновляется сразу после правки даты. База примеров записывается при первом запуске (раньше «Копия базы» была пустой до первого действия).

### Безопасность
- **Подписка на уведомления о заявках** шла по первым 8 символам id пространства, который лежит в адресе приёмника на сайте — любой мог подписаться на все ваши заявки. Теперь — секрет, который знает только владелец и который перевыпускается (в т.ч. автоматически при удалении сотрудника).
- **Личные контакты из личного Telegram** больше не превращаются в карточки клиентов, сделки и задачи в общей базе — заявка из личной переписки только рукой («Это клиент»).
- **Приёмник форм/Instagram**: лимит 20 заявок в минуту на пространство, поле-приманка для роботов, потолок на поля формы в журнале, телефон чистится, дедуп по ключам WhatsApp/MAX/Meta/Тильды, `/start` без текста не создаёт сделку и не шлёт уведомление. Telegram-вебхук проверяется только по заголовку (адрес с ключом виден в getWebhookInfo).
- **Код приглашения**: перевыпущенный код не подходил никому (регистр) — исправлено и в клиенте, и в базе; 60 бит вместо 32; пауза при промахе; при удалении сотрудника код перевыпускается сам.
- `chat_append_msg` (SECURITY DEFINER) была доступна с anon-ключом — любой мог дописать «сообщение клиента» в чужой диалог. Доступ отозван (`supabase-hardening.sql`).
- «Выйти и стереть на этом устройстве»: сессия личного Telegram и ключи каналов не остаются следующему человеку за общим ПК.
- CSP в странице: чужой скрипт с любого адреса не выполнится; экран спасения не вставляет текст ошибки как HTML. Сборка в CI — по lock-файлу (раньше каждый деплой тянул свежие версии ~400 пакетов).
- Временный мост webhook.site не показывается в облаке; журнал входящих чистится (60 дней).

### Переезд с другой CRM (импорт)
- **Стадии в файле → ваши стадии**: таблица сопоставления с автоподбором «успех/отказ/новая» по синонимам amoCRM/Битрикс («Успешно реализовано», «Закрыто и не реализовано», «Сделка провалена»…), создание недостающих стадий на месте. Раньше все закрытые сделки падали в «Новая».
- **Даты с временем** (`12.03.2025 14:22`), «Дата создания» → дата создания записи (сводка больше не считает перенесённый архив «новыми за неделю»), «Дата закрытия» → дата стадии; день рождения больше не подхватывает случайные даты.
- **Ответственный** из выгрузки сопоставляется с сотрудниками; **ФИО из трёх колонок** склеивается; **примечания** уходят в хронологию; **телефон** нормализуется (`8 916…` и `9,16E+09` → `+7 916 …`); **связь сделки с клиентом** ищется по телефону, а не только по точному имени; **ID из старой системы** сохраняется — повторный импорт обновляет, а не дублирует.
- Честная подсказка: XLSX пока не читается — пересохраните как CSV (Битрикс: «Экспорт в CSV», amo: «Экспорт»).

### Конструктор
- Новые типы полей: **«Да/нет»** и **«Несколько из списка»** — везде: карточка, таблица (галочка переключается прямо в ячейке), фильтры, экспорт, импорт.
- **Телефон как телефон**: `tel:`, WhatsApp и Telegram одним нажатием из карточки и таблицы; телефон в карточке канбана; телефон связанного клиента прямо под связью.
- **Связь с поиском** (по названию и телефону) вместо списка из всех записей; кнопка «открыть» связанную карточку.
- **Причина отказа**: при переносе в «Проиграна» появляется поле с вариантами (Дорого, Передумал, Не ответил, Ушёл к конкуренту, Другое) — и блок «Причины отказа» в сводке.
- **Дубли**: подсказка «похожая запись по телефону → Объединить» и пункт «Объединить с…».
- Новый раздел: без второго «Ответственного», с телефоном по умолчанию и множественным числом («Заказ → Заказы»).
- Демо-люди («Марина», «Артём») убираются вместе с примерами; своё имя — при выборе ниши; ниша «Своя — с нуля».
- Тач: чекбоксы и тумблеры не вытягиваются; конструктор на телефоне — в две строки; контраст мелких подписей.

### Автоматизации
- «Застряла на стадии» — теперь для **конкретной стадии** (правила пресетов больше не ставят задачи по чужим стадиям).
- Новое действие **«написать клиенту по шаблону»** (в диалог настоящего канала; нет диалога — задача вместо пустого срабатывания), новые триггеры **«клиент ждёт ответа N часов»** и **«за N дней до даты в поле»**; ночью письма ждут утра.

### Сводка
- Работает для справочников (раньше роняла приложение). Период (неделя/месяц/квартал/год/всё), **таблица по сотрудникам** (в работе, выиграно, конверсия, просрочено), деньги по стадиям, причины отказа, события только по разделу.

## Что осталось и почему не сделано сейчас
- **Права «сотрудник видит только свои»** — нужны изменения RLS и роли в базе; это следующий серверный шаг (без него владелец с наёмными менеджерами отдаёт им всю базу).
- **XLSX на входе** — библиотека чтения весит ~300 КБ и в single-file сборке легла бы всем; сначала стоит вынести GramJS (1,3 МБ, 55 % бандла) в отдельный файл.
- **Ответы в Instagram через Meta**, канал **Avito/VK**, ежедневный дайджест задач в Telegram — серверные задачи следующей версии.
- Резервные копии облака (free-план Supabase без бэкапов) — ночной `pg_dump` в GitHub Actions.
- Свой домен для Pages — изолирует localStorage от других страниц аккаунта github.io.

## Чего не делать (чтобы не раздуть)
Телефония/АТС и почтовый клиент; визуальный конструктор бизнес-процессов с ветвлениями; счета, склад, товары; гранулярные матрицы прав; нативные приложения и маркетплейс интеграций. Каждое из этого — отдельный продукт, а переходят к нам не из-за него.
